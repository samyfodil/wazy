# wazy-build-csharp

`ghcr.io/samyfodil/wazy-build-csharp:0.8.0-preview00011-net10.0.402`

| Tool | Version |
| --- | --- |
| .NET SDK | 10.0.402 |
| componentize-dotnet (`BytecodeAlliance.Componentize.DotNet.Wasm.SDK`) | 0.8.0-preview00011 |
| NativeAOT-LLVM (`runtime.linux-*.microsoft.dotnet.ilcompiler.llvm`) | 10.0.0-rc.1.26306.1 |
| wasi-sdk | 29.0 (the version NativeAOT-LLVM expects) |
| shared wasm tools | see [the index](../README.md#shared-tools) |

These are preview toolchains, and the image is large (most of it is the
NativeAOT-LLVM compiler). The NuGet cache in `/opt/nuget` is warmed with
exactly the packages above, so a project that references those versions
restores without downloading them.

## Build

```sh
docker run --rm -v "$PWD":/src -w /src --user "$(id -u):$(id -g)" \
  ghcr.io/samyfodil/wazy-build-csharp:0.8.0-preview00011-net10.0.402 \
  dotnet build -c Release
```

The component is `bin/Release/net10.0/wasi-wasm/native/<project>.wasm`.

## A minimal project

Copy [`sample/hello`](sample/hello) and [`sample/nuget.config`](sample/nuget.config)
(componentize-dotnet's packages come from the `dotnet-experimental` feed), then:

```sh
cd hello
docker run --rm -v "$PWD":/src -w /src --user "$(id -u):$(id -g)" \
  ghcr.io/samyfodil/wazy-build-csharp:0.8.0-preview00011-net10.0.402 \
  dotnet build -c Release
go run github.com/samyfodil/wazy/build-images/runner@latest run bin/Release/net10.0/wasi-wasm/native/hello.wasm
```

```
hello from csharp
```

`hello.csproj` picks the NativeAOT-LLVM package for the build machine's
architecture; componentize-dotnet's template only lists linux-x64.

## Sample

[`sample/build.sh`](sample/build.sh) builds `wasi:cli/command` (`hello/`) and
`wasi:http/proxy` (`proxy/`, bindings generated by componentize-dotnet from
`proxy/wit`). NativeAOT optimizes at link time and links the core modules
itself, so the optimized variants are `wasm-tools strip --all` of the
finished components (about a third of the size).
